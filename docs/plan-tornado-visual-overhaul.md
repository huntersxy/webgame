# 实施方案：《龙卷风成长记》画面重制（vgpu / WebGPU）

> 状态：**已实施**（P0–P5 全部完成）。计划内容保留在下方备查。
> 三项决策均经维护者拍板：倾斜正交相机（pitch 60°）、3D 底座 + emoji 顶面贴花、
> 网格漏斗 + 程序化螺纹；`tornado-backend-compare` 的判据由「像素一致」改为「玩法一致」。
>
> 实施期间发现并修正的实际问题（计划未预见）：
> · 主相机把世界 y 翻成屏幕 y，会翻转三角形绕序 → 必须声明 `frontFace: "cw"`，
>   否则 `cull: "back"` 剔掉的正是该看见的面；
> · `set()` / `Buffer.write()` 底层是 `queue.writeBuffer`，在提交前全部生效，
>   多趟共用同一个 uniform 缓冲会互相覆盖 → 泛光三趟各用独立缓冲；
> · `textureSampleCompare` 只能用于片元阶段 → 阴影计算从顶点阶段移到片元阶段；
> · 深度范围必须覆盖相机前后（取负近平面），否则相机附近的地面会被整片裁掉；
> · 移轴景深与泛光都要克制：虚化区里放着玩家要吃的东西，泛光阈值必须高于地表亮度；
> · 碎屑的 billboard 尺寸必须用**屏幕**半径而不是世界半径，
>   否则高量级（世界半径上百）时每块碎屑会盖住整个屏幕。
>
> 目标读者：项目维护者。

---

## 0. 目标与硬约束

**目标**：把当前「平面色块 + emoji 卡片」的原型观感，重制成有体积、有光照、有氛围的成品画面。

**硬约束**（来自项目既有承诺，不可违反）：

| 约束 | 来源 |
| --- | --- |
| 操作仍是**上帝视角 + 世界 XY 轴**，不改玩法与手感 | 本次明确要求 |
| 仓库**不存第三方 UI / 美术素材** | README「程序化美术」一节 |
| 无 WebGPU 的浏览器仍可玩（Canvas 2D 兜底） | README、控制器 `fallbackToCanvas2d` |
| 模拟层与渲染层分离，两个后端共用同一份派生状态 | `game.ts` 的 `renderState()` 契约 |

---

## 1. 现状诊断：为什么看起来平

不是「着色器写得不够花」，而是**画面里没有任何一条能产生体积感的信息通道**。逐条对照当前四趟管线：

| 现象 | 根因 | 位置 |
| --- | --- | --- |
| 大片纯色方块，读起来像色板 | 地貌格只有「一种颜色 + 一点明暗抖动」，没有纹理、没有高度、没有边界过渡 | `shaders.ts` `FLOOR_WGSL` |
| 物体像贴在桌面上的卡片 | 每个物体是「圆角矩形底板 + emoji 贴图」两层**屏幕对齐**四边形，没有高度、没有朝向、没有自阴影 | `renderer.ts` `collect()` |
| 场景没有光影关系 | **完全没有光照通道**：没有法线、没有光源、没有阴影贴图 | 全局 |
| 龙卷风几乎看不见 | 解析 SDF 画的是屏幕空间淡色椭圆环，不参与深度、不遮挡也不被遮挡 | `shaders.ts` `TORNADO_WGSL` |
| 地表与物体之间没有接触感 | 唯一的「阴影」是一枚恒定 alpha 的扁椭圆 | `renderer.ts` 地形/物体阴影 |
| 没有镜头语言 | 纯俯视正交、无景深、无暗角之外的后处理，整个画面同一景别 | `COMPOSITE_WGSL` |

**关键判断**：当前架构里**深度缓冲根本不存在**——所有绘制都是全屏 effect 或屏幕对齐四边形，深度测试无从谈起。这是「平」的结构性原因，也是本次改造的核心。

---

## 2. 目标画面语言

方向定为**「倾斜的沙盘模型 / 微缩立体模型（diorama）」**：

- 相机倾斜后能看到建筑的侧面与高度，物体真正「立」在地面上；
- 长方向性阴影把物体钉在地面上，产生接触感；
- 后期用**移轴景深（tilt-shift）**把画面上下缘虚化，强化「这是个精致的微缩模型」的错觉；
- 龙卷风是唯一贯穿画面的动态主体，带真实体积与环绕碎屑；
- 色彩分级统一到「明亮、通透、略偏冷的日光」。

这套语言的选择理由很直接：**它能在完全不改玩法、不引入美术素材的前提下，把俯视游戏做成有质感的成品**——移轴景深恰好是俯视视角收益最高的单点技巧。

## 3. 三个关键决策

决策由 jev 在候选方案中选出（`needs_creator_signoff = true`，即需要你最终拍板，本文即为提请）。

### 决策 A：相机 = **倾斜正交**（pitch ≈ 60°）

| 方案 | 结论 |
| --- | --- |
| 纯俯视正交 | ❌ 加不了高度与投影，物体永远是平的 |
| **倾斜正交** | ✅ **采用** |
| 倾斜透视 | ❌ 远处缩小 → 世界坐标在屏幕上的读法不再一致，破坏「上帝视角 XY」 |

**为什么倾斜正交能同时满足「立体」和「上帝视角 XY」**：正交投影下，世界 → 屏幕是**仿射变换**，没有透视除法，因此

```
screen_x = (gx - camx) * s
screen_y = (gy - camy) * s * sinθ - h * s * cosθ        θ = 俯角
```

- 尺度在屏幕上处处均匀（这正是「上帝视角」的手感来源）；
- 逆变换是闭式的、线性的，指针拾取（`screenToWorld`）精确可逆；
- 世界 XY 的移动方向与屏幕方向仍是固定线性关系，玩家不会感到操作被扭曲。

若改用透视，逆变换是投影除法，同一段世界位移在不同屏幕位置对应不同像素位移，XY 操作手感会漂——因此排除。

**俯角取值**：θ = 60°（地面压缩 `sinθ ≈ 0.87`，高度增益 `cosθ = 0.5`）。可调区间 52°–68°：θ 越小越立体但地面越挤。此常数留作视觉调试项，不写死语义。

### 决策 B：世界几何 = **3D 底座 + emoji 贴花**（混合）

| 方案 | 结论 |
| --- | --- |
| 保持 emoji 广告牌 | ❌ 画面本质仍是平的 |
| 全部换成程序化 3D 网格 | ❌ 丢失 emoji 识别度，且每个物体都要建模 |
| **3D 底座 + emoji 贴花** | ✅ **采用** |

每个物体渲染为：**真实立体的底座**（按量级与物体尺寸拉伸的盒体/柱体，带法线与受光）＋**贴在底座顶面的 emoji 贴花**。

- 保住 emoji 作为视觉身份，也保住「零第三方素材」承诺（emoji 来自系统字体，与现状一致）；
- 顶面贴花在倾斜视角下被正确透视压缩，读起来像**摆在沙盘上的棋子**——与目标画面语言一致；
- 获得真实高度、侧面受光、方向性投影与自阴影。

### 决策 C：龙卷风 = **网格锥体 + GPU 碎屑**

| 方案 | 结论 |
| --- | --- |
| 保持解析 SDF | ❌ 主体仍是平的 |
| **网格锥体 + 碎屑** | ✅ **采用** |
| 体素 raymarch | ❌ 收益/成本比最差 |

用实例化的**锥体网格**（沿高度堆叠的渐缩环，带扭曲）渲染漏斗，走深度测试与光照；碎屑改为**实例化粒子**，在漏斗内做螺旋运动。这样龙卷风会正确遮挡城市、也被城市遮挡，成为真正的主体。

## 4. 渲染管线架构

> **重要前提**：vgpu 0.5.0 **没有场景图渲染器**。`vgpu/scene` 只导出 CPU 侧描述符（几何配方、相机、材质、灯光、场景树），源码中不存在 `gpu.scene()` 或任何遍历渲染入口。因此所有 3D 都必须在 `draw()` + 自写 WGSL + 自建实例流之上实现。这一点已核实，方案据此设计。

每帧渲染顺序：

| # | Pass | 目标 | 内容 |
| --- | --- | --- | --- |
| 1 | 阴影 | `depth32float`，1024²/2048² | 仅深度：所有投影体按太阳正交矩阵绘制 |
| 2a | 地表 | `rgba16float + depth + MSAA4` | 全屏：屏幕 → 世界逆变换，程序化地貌 + 高度法线 |
| 2b | 地形障碍 | 同上，`clear:false` | 实例化网格：山=锥、湖=扁盘、巨石=多面体、林=锥簇 |
| 2c | 物体 | 同上 | 实例化：3D 底座 + 顶面 emoji 贴花，采样阴影贴图 |
| 2d | 龙卷风 | 同上 | 实例化锥体 + 碎屑粒子，半透明，深度测试开、深度写关 |
| 2e | 粒子/环 | 同上 | 实例化，加法/透明混合 |
| 3 | 亮部提取 | 半分辨率 HDR | 阈值 + 软膝 |
| 4 | 模糊 ×N | ping-pong 半分辨率 | 分离高斯，多级 |
| 5 | 合成 | canvas surface | 泛光叠加 + 移轴景深 + 暗角 + 调色 + 风眼擦除 + 信箱边条 |
| 6 | 文字覆盖 | canvas surface | 中文题字/字幕（沿用现有 2D 覆盖画布贴图） |

**已在本机设备上实测通过的能力**（非假设，均为真实 WebGPU 设备回读验证）：

- `depth32float` 目标；将 `target.depth` 绑定为 `texture_depth_2d` + `sampler_comparison` + `textureSampleCompare` → 回读得到正确亮部值（**阴影贴图可用**）；
- 实例化绘制（`stepMode: 'instance'` 顶点流）；
- `rgba16float` + MSAA 4× + 深度 的组合目标，且 `effect.compile()` / `draw.compile()` 可预热；
- `pingPong()` 目标对、`bundle()` + `p.bundles()` 重放；
- `compute()` + storage buffer、`clock()`。

**一个已踩到的坑（务必记录）**：自定义 `GeometryLike` 时，`draw()` 通过 `geometry.vertexBuffers` 逐槽 `setVertexBuffer`；若只提供 `vertexBufferLayouts` 而漏掉 `vertexBuffers`，运行期报 `Vertex buffer slot N required by [RenderPipeline] was not set`。拼接「几何配方 + 自有实例流」时必须同时给出 `vertexBuffers`（`GPUBuffer[]`）与 `vertexBufferLayouts`。几何配方暴露的顶点布局为 `position@0 float32x3` / `normal@1 float32x3`（stride 24），自有实例流从 `shaderLocation 2` 起追加。

## 5. 世界几何：实现细节

**物体底座**：按物体半径生成实例，几何为单个共享盒体；实例流携带 `(世界位置, 高度, 朝向, 色调)`。同量级共享一次 draw call。

**emoji 贴花**：沿用现有图集（`atlas.ts` 无需改动），改为绘制在底座**顶面**的四边形，法线朝上、随底座受光。图集纹理继续复用。

**地形障碍**：

| 种类 | 网格 | 说明 |
| --- | --- | --- |
| 山 `mount` | 锥体 ×3 | 保留现有「三峰 + 雪顶」构图，改为真实锥体 + 雪线材质 |
| 湖 `lake` | 扁圆盘 | 写入深度、参与反射式高光；岸线由地表着色器做湿边 |
| 巨石 `boulder` | 多面体 | 复用现有三块叠放构图 |
| 林 `forest` | 锥簇 | 每株一个实例，低成本高密度 |

**关键约束**：碰撞判定**完全不动**——仍是世界 XY 平面上的圆形判定（`game.ts` 的 `reach` 逻辑）。倾斜只发生在渲染层。

## 6. 地表

在现有 `FLOOR_WGSL` 基础上：

1. 屏幕 → 世界改为上述**倾斜仿射逆变换**；
2. 由程序化高度场求法线，得到真实的日照明暗与地形起伏；
3. 保留现有 `hashInt` 逐位一致的整数哈希（JS 与 WGSL 位模式相同），**地貌分布不因改造而改变**；
4. 地貌格之间加过渡（现有实现是硬边方块，这是「像色板」的直接原因）；
5. 水面单独处理：法线扰动 + 高光。

## 7. 后期处理

| 效果 | 做法 | 价值 |
| --- | --- | --- |
| **移轴景深** | 按屏幕 Y 的带状模糊，聚焦带随镜头微调 | 最高性价比，直接产出「微缩模型」观感 |
| 泛光 | 亮部阈值 + 多级模糊叠加 | 让龙卷风碎屑、水面高光发光 |
| 接触阴影 | 阴影贴图 + 屏幕空间接触阴影 | 物体「钉」在地面上 |

| 暗角 / 信箱边条 / 风眼擦除 | 保留现有实现 | 不破坏既有转场语义 |

后期链路全部在半分辨率上做，控制填充率开销。

## 8. 对既有代码与测试的影响

**这一节需要你特别过目**，因为本次改造会让一条既有测试的**前提失效**。

| 项 | 影响 | 处理 |
| --- | --- | --- |
| `src/tornado/game.ts` | 模拟、碰撞、计分、连招、转场**均不改** | 仅在 `renderState()` 中补充相机基（俯角/基向量）供渲染层使用 |
| `src/tornado/gpu/*` | 大规模重写 | 新增阴影、网格、后期相关模块 |
| `scripts/tornado-backend-compare.mjs` | ⚠️ **前提失效**：该脚本断言两个后端渲染出**像素级近似相同**的画面。3D 化后 Canvas 2D 无法（也不应）复刻同样的光影，逐像素对照不再成立 | 建议**改判据**：从「像素一致」改为「**玩法一致**」——同一确定性世界、同一相机锚点、同一吞噬结果，外加「两个后端都渲染出非空画面」。**这是本次唯一需要你认可的测试语义变更。** |
| `scripts/check-shaders.mjs` | 新增着色器需纳入校验 | 追加到 `targets` 列表 |
| `scripts/tornado-smoke.mjs` | 断言基于 HUD 与状态，基本不受影响 | 复核 |
| `src/controllers/tornado-controller.ts` | 兜底路径 | 见下 |

**Canvas 2D 兜底怎么办**：倾斜正交对地面而言仍是仿射变换（`screen_y` 只需乘 `sinθ`），因此 Canvas 2D **技术上可以实现同一投影**；但完整复刻光影、阴影、泛光不现实。建议兜底保持「同投影、简化着色」——玩法与构图一致，质感降级。若你更希望兜底维持现状（纯俯视、零改动），也可，但两个后端的构图会不一致。

## 10. 验证方案

遵循项目既有节奏：**本地只跑与本次改动相关的定向冒烟（十几秒级），全量交给 CI**。

1. **着色器**：`npm run check:shaders`（设备级校验，扩展新着色器）；
2. **画面证据**：headless 截图 + PNG 解码统计（不依赖肉眼，也不依赖 `drawImage` 读回 WebGPU 画布——该做法已知会得到全透明）；
3. **玩法未回归**：`npm run test:tornado:smoke`（HUD、连击、冲刺、目标）；
4. **站点未牵连**：`npm run test:site`（九条路由 + PWA 离线）；
5. **性能**：用 `timer(gpu)` 量各 pass 的 GPU 耗时，设定预算（目标 1080p / DPR2 下主流程 < 8ms），必要时按帧健康度降级（降 DPR 或关 MSAA）。

## 11. 风险与开放问题

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| **相机倾斜是唯一动到全局几何的改动** | 可见世界范围从 `VIEW/s` 变为 `VIEW/(s·sinθ)`，影响地表 LOD、物体剔除、相机边界钳制 | 集中在 P0 处理并逐项验证 |
| 指针拾取 | 若逆变换未同步更新，点选会系统性偏移 | P0 内用单元测试钉死正/逆变换互逆 |
| 性能 | MSAA4 + HDR + 阴影 + 泛光对核显压力大 | 半分辨率后期、阴影贴图降分辨率、按帧健康度降级 |
| 半透明排序 | 龙卷风与粒子需要正确的深度写开关组合 | 深度测试开 / 深度写关，按距离排序 |
| 包体 | 新着色器与网格逻辑会增大渲染器分块 | 该分块本就是**动态 import**，主包与其余八款游戏不受影响 |
| 兜底观感落差 | 两后端质感差距会拉大 | 见 §8，需你选择口径 |

**需要你拍板的三件事**：

1. 相机倾斜正交（pitch 60°）是否认可——这是本次改造的地基；
2. 「3D 底座 + emoji 贴花」是否认可——决定 emoji 视觉身份的保留方式；
3. `tornado-backend-compare` 的判据由「像素一致」改为「玩法一致」是否认可——**唯一影响既有测试语义的变更**。

## 12. 明确不做的事

- 不改任何玩法规则、数值、碰撞判定与计分；
- 不引入任何图片 / 模型 / 字体等第三方美术素材；
- 不改成透视相机（会破坏上帝视角 XY 手感）；
- 不做体素 raymarch 龙卷风（成本收益比最差）；
- 不改动站点其余八款游戏。
